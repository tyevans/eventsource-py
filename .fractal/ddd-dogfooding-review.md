# Domain Ring Review: DDD Fidelity & Dogfooding

Reviewer: fresh senior DDD/event-sourcing reviewer. Scope: `src/eventsource/domain/` at main b7878b8 (post-PR #103), plus docs/tests/application as consumers. All counts reproducible via the grep commands quoted inline.

## Executive summary

- The domain ring is a genuine DDD artifact, not a state-container framework: consistency boundaries are real (version validation, atomic command rejection, uncommitted-event tracking), invariants land naturally in `decide()`/command methods, and provenance is a first-class concept. This is the strongest ring in the library.
- **Headline dogfooding failure: the flagship style is invisible at both front doors.** `docs/index.md` and `docs/getting-started.md` contain zero mentions of `DeciderAggregate` (ADR-0022 §5: "the decider is the primary showcased style"). In the library's own tests, decider aggregates are 4 of 59 concrete aggregate definitions (~7%); docs-wide, 12 of 40 (30%).
- **The quickstart actively contradicts a written architecture rule**: `.claude/rules/architecture.md:218` says event_type is auto-derived, "never declare it by hand" — `docs/getting-started.md` declares it by hand three times and calls that "the clearest option"; tests hand-declare it on 252 lines; two domain-module docstrings model the same stale pattern.
- Ubiquitous language is coherent at the core (DomainEvent/DomainCommand/decide/evolve/`CommandRejectedError` = "the domain said no") with a few residual splits: `StreamId.category` vs `aggregate_type` are two names for one concept with the validity invariant enforced on only one of them; `domain/types.py`'s eight vocabulary aliases are exported but used by zero internal call sites.
- Internal consumption is clean — application ring, testing toolkit, and repository all consume domain through the promoted surface (StreamId, `get_required_tenant`, `DeciderScenario` exists and is good). The drift is entirely in the *teaching* layer (docs, examples, test fixtures), which is fixable without breaking anything.

## DDD fidelity findings

### Aggregate design: real boundaries, three deliberate escape hatches

The three styles form a genuine consistency boundary, not an anemic wrapper:

- `apply_event()` enforces monotonic versioning on every new event (`aggregate.py:219-229`), raising `EventVersionError` on gaps or regressions.
- `DeciderAggregate.execute()` is atomic-by-construction: `decide()` runs to completion before any event is applied (`decider.py:88-94`), so a rejection leaves no version bump and no uncommitted events. This is exactly the right shape — the framework makes the correct invariant placement (in `decide`) the *only* placement, because `evolve` never sees an event that `decide` didn't emit.
- `evolve` is documented as a total function ("case _: return state", `decider.py:53`), correctly steering invariant checks *out* of the evolution path.
- The state-in-a-pydantic-model pattern (`TState`) is not anemic-domain-model: behavior and invariants live on the aggregate; the state object is a deliberately passive fold accumulator, orthodox for functional event sourcing.

Escape hatches that weaken the boundary, in descending order of concern:

1. **`aggregate_type: str = "Unknown"` default** (`aggregate.py:133`). A subclass that forgets to set it silently writes events and streams typed `"Unknown"` — and `AggregateRepository._infer_aggregate_type()` happily infers it (`application/aggregates/repository.py:265-266`; the `hasattr` check passes because the base class provides the attribute). DDD says aggregate identity is not optional. This should be abstract/required, or at minimum the repository should refuse to infer `"Unknown"`.
2. **`create_event()` advertises overriding `aggregate_version`** (`aggregate.py:431-433`: "passing `aggregate_version=5` will use 5 instead of the calculated next version"). Version stamping is the aggregate's consistency mechanism; documenting the bypass as a convenience feature invites misuse. The capability may need to exist (event upcasting, tests); the docstring shouldn't market it.
3. **`unregistered_event_handling = "ignore"` default on `DeclarativeAggregate`** (`aggregate.py:705`). For a *projection*, silently skipping unknown events is forward-compatible pragmatism. For an *aggregate* — the write model whose state feeds invariant checks — a silently unapplied event means `decide`/command methods reason over divergent state. The default protects backward compatibility today; a future major should flip aggregates to `"error"` (projections can keep `"ignore"`).
4. `apply_event(event, is_new=True)` is public, so application code can inject events past every command method. Inherent to the imperative style and needed by `_raise_event`/`create_event`; not fixable without breaking the style, just worth naming as the cost of keeping AggregateRoot around.

### Ubiquitous language: coherent core, three residual splits

The core vocabulary hangs together well: events past-tense, commands imperative, `caused_by(event)` / `with_causation(event)` / `is_correlated_with(event)` read as domain sentences, and `CommandRejectedError` is explicitly defined as "the domain said no" (`exceptions.py:58-65`) — a genuinely good piece of language design.

Residual issues:

- **`category` vs `aggregate_type`**: `stream_id.py:15-16` admits "`category` is today's aggregate type." Two names for one concept, in the same ring, on the two objects users touch most. Worse, the invariant is asymmetric — see Value objects below. Pick one term (category is the better long-term word if streams may outgrow aggregates; aggregate_type is the cheaper one to keep) and alias the other in docs only.
- **`domain/types.py` is dead vocabulary** (`types.py:12-23`). `AggregateId`, `EventId`, `TenantId`, `CorrelationId`, `CausationId`, `Version`, `StreamPosition`, `GlobalPosition` are publicly exported but consumed by zero internal call sites (`grep -rn "TenantId\|CausationId\|AggregateId" src/eventsource --include="*.py"` excluding types/init: empty). `DomainEvent` fields are typed raw `UUID`/`int` (`event.py:84-137`), so the published vocabulary and the actual signatures disagree. Two of the aliases are also mis-shaped as language: `TenantId = UUID | None` and `CausationId = UUID | None` bake *optionality of the association* into the *identity type* — a tenant id is a UUID; it's the event's reference to one that's optional.
- **`StreamPosition = int` / `GlobalPosition = int` contradict the architecture rule** that global positions are "opaque ordered tokens defined by the adapter" (`.claude/rules/architecture.md:187-189`). The real value object exists — `ports/positions.py:11` (`Position`, with cross-store comparability guards). The domain aliases predate it and now mislead.
- `EventBusError`/`EventStoreError`/`SerializationError`/`ProjectionError` remain domain-ring (`exceptions.py:39-93`). ADR-0041 deliberated this and kept them as general-purpose roots; I won't relitigate, but note the claim that these are "markers domain code itself raises" is thin — no domain module raises any of them. They're hierarchy anchors, and that's the honest description.
- Versioning vocabulary is heavy: `event_version` (event schema), `aggregate_version` (stream position), `schema_version` (snapshot schema), `Version` (dead alias). Each is individually justified; together they demand a glossary. Docs handle this adequately; no change recommended, just don't add a fifth.

### Value objects: right restraint overall, one invariant worth buying

- `StreamId` is a model citizen: frozen, slotted, validated (`CATEGORY_PATTERN` with the `\Z`-anchor subtlety documented, `stream_id.py:7-9`), wire-format-owning. Well dogfooded: 49 test files, 23 docs files, and the repository builds streams through it (`repository.py:283-285`).
- **The one asymmetry that buys a real invariant: `DomainEvent.aggregate_type` is an unvalidated `str`** (`event.py:107-110`) while the same value used as `StreamId.category` is pattern-validated (`stream_id.py:24-28`). An event constructed with `aggregate_type="Or:der"` is legal today and only detonates when someone renders a stream id from it. Validating `aggregate_type` against `CATEGORY_PATTERN` in `DomainEvent` (a one-line field validator) closes the gap without introducing a new type. A full `Category` VO shared by both is the orthodox move but buys nothing further — recommend the validator, not the VO.
- `aggregate_version`/`event_version` as bare `int`: correct. The architecture rule itself notes per-stream versions must be integers for optimistic concurrency arithmetic. A `Version` VO would be ceremony.
- Money as `float` in teaching material: `getting-started.md` (`initial_balance: float`, `amount: float`), `domain/tenant_events.py:58` docstring (`price: float`), 16 occurrences across docs and domain docstrings. For a library positioning itself as a DDD teaching artifact, float money in the flagship bank-account example is the classic red flag reviewers will seize on. Use `Decimal` or integer cents in at least the quickstart.

### Commands: optional-by-design is principled, but the type system is left idle

ADR-0022's structural-typing decision (`execute(command: object)`, `isinstance(command, DomainCommand)` unlocks provenance) is the right boundary: forcing `DomainCommand` would couple userland deciders to the library base class, destroying the pattern's purity selling point, and `_provenance_updates()` (`aggregate.py:451-480`) makes the opt-in seamless with correct explicit-wins precedence.

The cost is that `decide(command: Any, state)` (`decider.py:47`) erases all type help at the domain's most important entry point — no exhaustiveness checking on the command match, no IDE support. This is recoverable without touching the ADR: parameterize `DeciderAggregate[TCommand, TState]` (defaulted `TCommand = object` via PEP 696 / typing_extensions so existing single-parameter subscripts keep working). Then `decide(command: OrderCommand, state)` type-checks against a userland union and mypy flags the unhandled command. Illegal states stay representable at runtime (by design); they stop being *invisible* at type-check time.

### Invariant placement: metadata and tenant judged

- `metadata: dict[str, Any]` on every event (`event.py:140-143`): with `extra="forbid"` now on typed fields, the open metadata dict is the correct pressure valve — trace ids, request context, migration breadcrumbs need somewhere to live that isn't a schema migration. Orthodoxy would demand a typed envelope; the cost/benefit is clearly against it. **Pragmatism right.**
- Tenant as ambient context: orthodoxy says dependencies flow through signatures, not ambient state. The implementation earns its exception: LIFO-enforced tokens with loud failure (`tenant_context.py:269-280`), hard-clear invalidating all tokens (`tenant_context.py:283-316`), context stored in a `ContextVar` tuple precisely to prevent cross-task leakage (`tenant_context.py:99-107`), and — critically — the precedence order keeps the model explicit-first: explicit kwarg > `command.tenant_id` > ambient context (`aggregate.py:472-479`). The ambient value is a fallback, never an override. **Pragmatism right**, and the engineering around it is better than most production multi-tenant code I've reviewed.

## Dogfooding findings (with counts)

Count command for aggregate definitions: `grep -rnE "class \w+\((AggregateRoot|DeclarativeAggregate|DeciderAggregate)" <dir>`.

|---|---|---|---|---|
| `tests/` | 26 | 29 | 4 | 7% |
| `docs/` | 16 | 12 | 12 | 30% |
| `examples/` (runnable) | 5 | 1 | 1 | 1 of 7 |
| `bench/` | 0 | 1 | 1 | — |

File-level mentions (`grep -rl`): `DeciderAggregate` appears in 13 docs files — but subtract 6 ADR/superpowers files and the user-facing count is 7, vs 35 files mentioning `DeclarativeAggregate`.

1. **The two front doors never say "decider."** `docs/index.md`: 0 occurrences (its concepts section presents `AggregateRoot` + `DeclarativeAggregate` only, `index.md:335-340`). `docs/getting-started.md`: 0 occurrences; its worked example is a hand-written `_apply` imperative aggregate (`getting-started.md:381`). A new user completes the entire quickstart without learning the library's primary style exists. This directly contravenes ADR-0022 §5 ("examples, tutorials, and general-purpose fixtures lead with it").
2. **ADR-0022's "one worked reference example each" for the legacy styles is violated ~14x over**: docs contain 16 `AggregateRoot` and 12 `DeclarativeAggregate` worked definitions.
3. **`docs/explanation/aggregate-styles.md` has the emphasis inverted**: titled "AggregateRoot vs DeclarativeAggregate", opens with "two ways to write an aggregate," and introduces the *primary* style as "There is also a third style" in paragraph six (`aggregate-styles.md:1-8, 33-38`).
4. **Tutorial drift is split**: `tutorials/03-first-aggregate.md` is exemplary — full decider walkthrough, explicitly states decider "is the style this library recommends" (`03-first-aggregate.md:867`). But `tutorials/08-testing.md`'s main worked example is `DeclarativeAggregate` (`08-testing.md:102`) with `DeciderScenario` relegated to Step 8 (`08-testing.md:676`); guides (`repository-pattern.md:63`, `snapshotting.md:197,242,1009`) and all four subscription/projection examples use legacy styles for their incidental aggregates.
5. **`event_type` hand-declaration is systemic and *recommended***. Rule: "never declare it by hand" (`.claude/rules/architecture.md:218`). Reality: `getting-started.md:212,223,233` declare it redundantly and `getting-started.md:265-267` says "Setting it explicitly, as the example does, is the clearest option" — a direct contradiction of the project's own rule. `tests/` contains 252 hand-declared `event_type: str = "..."` lines (`grep -rn 'event_type: str = "' tests/ | wc -l`); `tests/fixtures/events.py` hand-declares on all 10 shared event classes and uses `@register_event` zero times. (Legitimate uses — versioned wire names like `tutorials/02-first-event.md:673` — are fine and correctly explained.)
6. **Domain docstrings model stale patterns.** `aggregate.py:79-89` — the *flagship class docstring* on `AggregateRoot` — shows manual `event_type="OrderCreated"`, manual `aggregate_type`, manual version stamping, and no `@register_event`. `event_registry.py:15-16` and `event_registry.py:317,323` show redundant `event_type: str = "OrderCreated"` alongside `@register_event`. Meanwhile `command.py`, `decider.py`, `tenant_context.py`, and `tenant_events.py` docstrings are current — the staleness is concentrated in the two oldest modules.
7. **Internal consumption is clean (the good news).** Application ring: repository consumes `StreamId` (`repository.py:22,283-285`), infers `aggregate_type` from the class attribute as docs teach; `TenantAwareRepository` uses `get_required_tenant` and its docstring shows `tenant_scope` (`tenant_repository.py:17,56`). No internal module uses manual `set_current_tenant`/`reset` (`grep -rn "set_current_tenant" src/eventsource` excluding tenant_context: only `__init__` re-exports). Testing toolkit imports domain through the ring surface, ships `DeciderScenario` (`testing/bdd.py:366-460`) — a genuinely good decider-native harness — and `tests/fixtures/aggregates.py:225` does provide a decider `OrderAggregate` with real `DomainCommand`s, satisfying ADR-0022's fixtures clause at the shared-fixture level even though per-test aggregates overwhelmingly don't use it.
8. `tenant_scope` over manual set/reset: docs teach the promoted pattern (multi-tenant guide leads with `tenant_scope`, `guides/multi-tenant.md:114-131`; tutorial 16 has 22 `tenant_scope` vs 4 `set_current_tenant` mentions, the latter in the "manual counterpart" section). **No drift here.**
9. `DomainCommand` reaches only 4 user-facing docs files and 3 test files — consistent with the decider gap: the styles that dominate the docs predate commands.

## Prioritized recommendations

1. **Rewrite the front doors around the decider** — `docs/getting-started.md` quickstart to `DeciderAggregate` + `DomainCommand` + `CommandRejectedError`; add decider to `docs/index.md`'s concept tour. Effort **L** (getting-started is long-form prose). Buys: the single highest-leverage coherence fix — first contact teaches the flagship, ADR-0022 §5 becomes true. Not breaking.
2. **Fix the event_type contradiction** — flip `getting-started.md:265-267` to recommend omission (auto-derive), drop the redundant declarations at `:212,223,233`; refresh `aggregate.py:79-89` and `event_registry.py:15-16,317` docstrings to current practice (`@register_event`, auto-derived names, `create_event`). Effort **S**. Buys: the project's docs stop contradicting its own architecture rule. Not breaking.
3. **Guard aggregate identity** — remove the `"Unknown"` default on `AggregateRoot.aggregate_type` (`aggregate.py:133`) or make `AggregateRepository._infer_aggregate_type` reject it (`repository.py:265`); add a `CATEGORY_PATTERN` validator to `DomainEvent.aggregate_type` (`event.py:107`). Effort **S**. Buys: two silent-corruption paths become loud errors at construction time. **Technically breaking** (anyone relying on "Unknown" or exotic aggregate_type strings) — pre-1.0 no-shims policy makes now the time.
4. **Reconcile `domain/types.py` with reality** — delete `StreamPosition`/`GlobalPosition` (contradict the opaque-`Position` rule; `ports/positions.py` is the truth) and either thread the identity aliases through `DomainEvent`/`DomainCommand` signatures or delete them too; fix `TenantId`/`CausationId` shape if kept (identity is `UUID`; optionality belongs at the field). Effort **S**. Buys: published vocabulary matches actual signatures. **Breaking** for the removed exports (currently unused internally, so blast radius is external-only and pre-1.0).
5. **Retitle and restructure `aggregate-styles.md`** to a three-style comparison with decider first, and move `tutorials/08-testing.md`'s `DeciderScenario` section before the harness material (or make the main worked example a decider). Effort **M**. Buys: the explanation layer stops presenting the primary style as an afterthought. Not breaking.
6. **Parameterize `DeciderAggregate[TCommand, TState]`** with defaulted `TCommand` (PEP 696 via typing_extensions). Effort **M**. Buys: exhaustive command matching under mypy at the domain's front door without touching ADR-0022's structural-typing decision. Not breaking (default preserves single-param subscripts).
7. **Migrate `tests/fixtures/events.py`** to `@register_event` + auto-derived names, and prefer decider fixtures for new tests. Effort **S** for the fixture file; the full 252-line test sweep is **L** and can be opportunistic. Not breaking (test-only).
8. **(Major-version parking lot)** Flip `DeclarativeAggregate.unregistered_event_handling` default to `"error"` for aggregates (keep `"ignore"` for projections); stop documenting the `aggregate_version` override in `create_event` as a feature. Effort **S** each, **breaking**, hold for 1.0.

## Explicitly-fine list (orthodoxy would flag; I judge correct here)

- **`execute(command: object)` / no mandatory command type** — principled per ADR-0022; forcing `DomainCommand` would couple pure deciders to the framework. The `isinstance` unlock plus explicit-wins precedence is a clean gradual-typing boundary. (Recommendation 6 adds type help without changing this.)
- **`metadata: dict[str, Any]` on every event** — with `extra="forbid"` on the typed surface, an open metadata channel is the correct pressure valve for trace/request context; a typed envelope would be ceremony.
- **Ambient tenant context in the domain ring** — orthodoxy violation, right call: ContextVar is stdlib (ring purity holds), LIFO tokens fail loudly, hard-clear exists for request boundaries, and ambient is strictly a fallback below explicit and command values.
- **`actor_id: str | None` amid UUID identities** — actors originate in external identity systems that aren't UUID-shaped; forcing UUID would push fake conversions into userland.
- **`aggregate_version` as bare `int`** — optimistic concurrency needs arithmetic; the architecture rule says exactly this. A `Version` VO would obstruct.
- **Aggregate envelope fields (`aggregate_id/type/version`) denormalized onto every event** — orthodox event-sourcing envelope design, not a boundary leak.
- **`SnapshotError` rooted at `Exception`, not `EventSourceError`** — documented preserved contract (`exceptions.py:256-260`) with an explicit major-version note; correct discipline.
- **Commands never persisted, no command bus/registry** — principled minimalism per ADR-0022; a rejected command leaving no trace is a defensible CQRS stance, and audit-minded users can log commands at the application boundary.
- **`@handles` dispatch keyed by Python type rather than wire name** — correct for in-process dispatch; the registry owns the wire-name mapping, and conflating them would reintroduce the pre-`event_type_name()` ambiguity.
- **`DeclarativeAggregate._event_handlers` rebuilt per subclass in `__init_subclass__` with duplicate detection** — the hardening wave got this right; noted only to say it was checked as a consumer, not re-audited.
